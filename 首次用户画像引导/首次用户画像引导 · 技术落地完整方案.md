## 一、整体架构概览

```
测评完成 → UserDefaults 写入画像数据
    ↓
关闭结果页
    ↓
跳转 AI 助手页（AIAssistantView）
    ↓
检测 hasCompletedOnboarding == false
    ↓

    ↓

    ↓

    ↓
用户第一条真实消息 → 携带系统 Prompt → 正常调用 API
```

## 三、预制消息系统设计（不消耗 API 次数）

### 核心原则

预制消息是**本地渲染的伪消息**，外观与真实 AI 消息完全一致，但：
- 不发起任何网络请求
- 不计入用户的 AI 对话配额
- 保存进聊天历史，但有内部标记

### 消息数据模型

```swift
struct ChatMessage: Identifiable, Codable {
    let id: UUID
    let role: MessageRole        // .assistant / .user
    let content: MessageContent  // 见下方
    let timestamp: Date
    let isPrescripted: Bool      // true = 预制消息，false = 真实 AI 回复
    var isOnboardingMessage: Bool { isPrescripted }
}

enum MessageContent {
    case text(String)
    case textWithAnimation(String, animationItems: [String])  // 带配置动画
    case textWithImage(String, imageName: String, ctaButton: CTAButtonConfig?)
    case textOnly(String)
}

struct CTAButtonConfig {
    let title: String
    let action: CTAAction  // .showBackTapSetup / .showNotificationPermission 等
}
```

### 播放时序

```
进入页面后：

t=0.0s   → 显示消息1（文字逐字出现）
t=0.5s   → 开始配置动画（5个 ✔ 项，每0.3s一个，共1.5s）
t=2.5s   → 动画完成，同时在后台真实执行对应配置操作
t=3.0s   → 显示消息2（含图片/CTA按钮）
t=5.5s   → 显示消息3（Prompt 示例）
```

消息之间用 `TypingIndicator`（三个点动画）过渡，保持真实 AI 的感觉。

## 五、历史记录持久化

**方案：SwiftData（iOS 17+）或 CoreData**

聊天记录持久化到本地，包含所有预制消息和真实消息。

关键设计：

```swift
@Model
class ConversationSession {
    var id: UUID
    var personaType: String              // 创建时的画像类型
    var systemPrompt: String             // 对应的系统 Prompt
    var messages: [ChatMessage]          // 全部消息，含预制
    var createdAt: Date
    var onboardingCompletedAt: Date?
}
```

**读取逻辑：**
- 每次打开 AI 助手页，先查询是否存在 `ConversationSession`
- 存在 → 加载历史记录，直接展示（包含 Onboarding 消息）
- 不存在 → 创建新 Session，触发 Onboarding 流程

用户始终能向上滚动看到第一次的欢迎消息。

## 六、后续追问的上下文维护

这是最关键的一环。

### API 调用时的消息组装策略

```
[系统 Prompt]                          ← 始终在第一位，含画像信息
[预制消息] × N                         ← 不发送给 API（用户已看到，AI不需要"重新知道"）
[用户第1条真实消息]
[AI第1条真实回复]
[用户第2条真实消息]
...
```

**预制消息不进入 API 上下文**——因为系统 Prompt 已经告知 AI "我已完成这些配置"，无需重复。这样既节省 Token，又避免 AI 在回复里不必要地引用 Onboarding 内容。

### 上下文窗口管理

当对话条数增多，需要防止超过 Token 限制：

```
规则：
- 系统 Prompt：始终保留（约 300 tokens）
- 保留最近 20 条真实对话
- 超出部分：调用一次摘要 API，生成"对话摘要"替代早期记录
- 摘要格式：
  "用户此前主要问了：[主题列表]，
   关键信息：[用户提到的项目名/预算金额等]"
```

摘要存入 `ConversationSession.contextSummary`，插在系统 Prompt 之后、当前对话之前。

## 八、其他补充完善

### 8.1 重复触发防护

```swift
// 控制逻辑
if UserDefaults.standard.bool(forKey: "hasCompletedOnboarding") {
    // 直接展示历史记录，跳过 Onboarding
} else {
    // 执行 Onboarding 流程
}
// Onboarding 完成后立刻写入
UserDefaults.standard.set(true, forKey: "hasCompletedOnboarding")
```

防止重新做测评后重复触发（重测只更新画像标签，不重新 Onboarding）。

### 8.2 跳过机制

第一条消息出现后，右上角显示「跳过」按钮。点击后：
- 立即结束动画
- 所有预制消息标记为已发送（但不逐条显示）
- 页面滚动到最底部，进入正常聊天状态
- 系统 Prompt 正常写入，确保 AI 上下文完整

### 8.3 网络异常处理

预制消息阶段完全离线，无需处理。

用户第一条真实消息失败时：
- 消息气泡显示"发送失败"+ 重试按钮
- 系统 Prompt 和历史记录完整保留，重试时直接复用

### 8.4 图片资源处理

所有 5 张效果图**打包进 App Bundle（Assets.xcassets）**，不依赖网络：
- 命名规范：`onboarding_img_earner`、`onboarding_img_efficiency` 等
- 提供 @1x / @2x / @3x 三套
- 点击查看全图：使用 `fullScreenCover` + `ZoomableImageView`（支持双指缩放）

### 8.5 消息气泡的视觉标识

预制消息与真实 AI 消息外观相同，但内部数据有 `isPrescripted: true` 标记。

用途：
- 构建 API 上下文时过滤掉预制消息
- 后续如需统计用户真实对话次数，排除预制消息

### 8.6 C画像通知权限时机

通知权限弹窗不在动画阶段触发，而是在**第三条消息完全显示后延迟 1 秒**触发，确保用户已看到"提前提醒你"的价值再被要求授权，授权率最高。

### 8.7 画像变更场景

未来若用户重新测评，结果页关闭后：
- 不重新触发 Onboarding
- 更新 `userPersonaType` 等 UserDefaults 字段
- 更新 `aiSystemPrompt`（下一次对话生效）
- 在聊天中插入一条系统通知气泡："你的财务画像已更新为「xxx」"

## 十、一句话核心原则总结

| 问题 | 解法 |
|---|---|
| 画像信息如何传递 | UserDefaults → 生成系统 Prompt → 注入每次 API 调用 |
| 不消耗对话次数 | 预制消息本地渲染，`isPrescripted = true`，不调用 API |
| 存放位置 | `PersonaOnboardingScripts.swift` 本地常量，Phase 2 可迁移 Remote Config |
| 保留历史记录 | SwiftData 持久化全部消息（含预制） |
| 追问时上下文 | 系统 Prompt 始终携带，预制消息不进 API 上下文 |
| 项目创建 | 「日常」项目已存在，动画对应的是「设为主账本 + 初始化分类」 |
