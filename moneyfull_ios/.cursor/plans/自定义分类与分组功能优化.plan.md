# 新增分类Bug修复与自定义分组功能规划

## 1. 为什么现在新增类目后没有显示出来？

**原因分析：**
- 当你在某个分类（比如“吃喝”）下点击“新增”时，唤起了 `QuickAddCategorySheet`。
- 但是，当前的 `AppStore.addCategory` 方法底层只接收了 `name`, `icon`, `colorHex`，并没有接收 `groupName`（分组名）。
- 这导致所有新加的类目，其 `groupName` 都是空字符串 `""`。
- 我们在 UI 层的兜底逻辑中，把空字符串强行归入到了 **“其他”** 组。所以你新增的分类其实被丢进了“其他”或者隐藏了，而你当前停留在“吃喝” Tab，自然就看不见它了。

---

## 2. 新增类目（二级分类）时选择大分类的方案

**优化方案：**
1. **API 支持**：修改 `AppStore.addCategory`，增加 `groupName` 和 `transactionType` 参数。
2. **UI 增加分组器**：在 `QuickAddCategorySheet` 中，名称输入框下方，新增一行 **“所属分组”**。
3. **智能默认值**：
   - 既然用户是在 `CategorySelectionView` 里点击的新增，我们可以把用户当前所处的 `selectedTab` 传给弹窗。
   - 如果用户当前在“吃喝” Tab 点了新增，那弹窗里的“所属分组”就默认选中“吃喝”。
   - 如果用户是在“常用”或“全部”里点的，可以默认选中“其他”或者由用户自行下拉选择。

---

## 3. 是否能新增一级分类（大分类 Tab）？

**完全可以！而且非常有必要。**

目前我们的横向大类 Tab（吃喝、居家、出行等）在代码里是**写死**的固定数组。为了支持用户自定义大类（例如用户想建一个专门的“装修”大类或“宠物”大类），我们需要做以下改造：

### 3.1 动态生成横向 Tab
- 不再使用写死的数组，而是每次渲染时，遍历当前所有的分类（`typeCategories`），提取出所有不重复的 `groupName`。
- **排序规则**：
  - 第 1 位固定是：“常用”
  - 中间排**系统预设大类**（吃喝、居家、出行、娱乐、成长、人情、其他）
  - 接着排**用户自定义大类**（按创建时间或名称排序）
  - 最后 1 位固定是：“全部”

### 3.2 如何创建新的一级分类？
**轻量级解法（标签法）**：
- 由于我们并没有单独一张叫做“大分类”的数据库表，大类本质上是子分类身上贴的 `groupName` 标签。
- 所以，只要在 `QuickAddCategorySheet` 的“所属分组”选择器里，提供一个 **“+ 新增分组”** 的选项。
- 用户输入一个新名字（比如“装修”），然后建了一个子类（比如“买水泥”），保存后，数据库里有了一个 `groupName = "装修"` 的分类。
- UI 层的动态 Tab 逻辑一旦扫描到“装修”这个全新的 `groupName`，顶部就会立刻出现一个【装修】的 Tab。

### 3.3 系统的分类管理页 (`CategoryManagementView`) 升级
- 现有的全局分类管理页面还是平铺的。
- 升级计划：在分类管理页面中，采用**折叠面板（Section）**的形式，把分类按大类组织起来。
- 支持在管理页对分类进行**跨分组拖拽转移**（比如把“猫粮”从“居家”拖到新建的“宠物”大类里）。

## 4. 后续开发实施步骤拆解 (Task List)

1. **[数据层]** 改造 `AppStore.addCategory`，支持传入 `groupName`。
2. **[UI层]** 改造 `QuickAddCategorySheet`，增加“所属分组” Picker 菜单，支持接收默认传入的 `groupName`，并提供一个自定义新分组的入口。
3. **[UI层]** 改造 `CategorySelectionView`，将硬编码的 `tabs` 数组改为动态计算（提取当前所有去重的 `groupName`），保证新分组能立刻渲染出对应的 Tab。
4. **[管理层]** （可选进阶）重构 `CategoryManagementView`，按分组（Section）展示并支持大类的管理。
