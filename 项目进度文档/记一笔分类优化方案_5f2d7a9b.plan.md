# 记一笔分类选择优化方案

## 1. 背景与目标
当前“记一笔”页面分类平铺展示，随着分类数量增加，用户查找特定分类的效率变慢。
**目标**：通过引入“常用推荐”与“一二级分类”体系，提升用户查找和选择分类的速度，优化记账体验。

## 2. 核心交互方案

### 2.1 增加“常用”Tab（默认首页）
- **逻辑**：在所有分类 Tab 的最左侧新增「常用」Tab，作为打开“记一笔”时的默认视图。
- **内容**：自动抓取用户最近使用频率最高或最近使用的 8~12 个分类。
- **价值**：满足 80% 的日常记账场景，用户打开即可“盲点”记录，无需滑动切换。

### 2.2 横向一级 Tab 导航
- **UI布局**：在“分类”标题下方，新增一行横向滑动的文字 Tab 栏（如：`常用 | 吃喝 | 居家 | 出行 | 娱乐 ... | 全部`）。
- **交互**：点击 Tab 切换下方的九宫格图标面板，滑动下面板也可以联动切换 Tab。

### 2.3 “大类作为通用选项”机制
- **逻辑**：在每个具体的一级 Tab（例如“吃喝”）下的九宫格中，**第一个图标固定为该大类本身**（如“餐饮/吃喝(通用)”）。
- **价值**：解决“不想细分，只想随便记一笔吃喝”的懒人记账需求。

### 2.4 关于“全部”分类 Tab 的设计
- **位置**：放置在横向 Tab 的最右侧。
- **展示方式**：由于全部平铺容易眼花，建议在“全部”Tab下，采用**按一级分类分组（Section）**的形式展示（带小标题：吃喝、居家等），用户可以一直往下滑动浏览所有分类，适合找不到分类时进行全局查找。

## 4. 图标不全的补充方案

针对细分子类目增加导致的图标缺失问题，采用以下策略：

### 4.1 方案一：使用 iOS 原生 SF Symbols（推荐，开发成本最低）
iOS 提供了非常丰富的 SF Symbols 矢量图标库。我们可以建立一个映射字典（Mapping Dictionary），将类目名称映射到合适的 SF 符号上。
- **优点**：无需外部 UI 资源，支持动态颜色和大小，自带圆角，风格极其统一。
- **示例映射**：
  - `餐饮` -> `fork.knife`
  - `日用` -> `cart.fill`
  - `交通` -> `car.fill` / `bus.fill`
  - `医疗` -> `cross.case.fill`

### 4.2 方案二：图标复用与背景色区分
对于难以找到精确图标的子类，可以复用其一级分类的图标，但通过改变背景色或者图标颜色来进行区分。
例如，“吃喝”类目的基础色调是浅橙色/浅绿色，下面所有没有特定图标的子类都用同一个“吃喝”通用图标，但名称不同。

### 4.3 方案三：使用 Emoji 作为图标替代
如果某些分类（如“麻将”、“宠物”）很难找到完美的 SF Symbol，可以直接使用 Emoji。Emoji 表现力强，且带有天然的亲和力。
- 例如：`麻将` -> 🀄️，`宠物` -> 🐶

**最终实施建议**：
优先使用已有的自定义切图 -> 缺失部分映射到 **SF Symbols** -> 极少数没有合适符号的采用 **Emoji**。这样既能保证功能完整，又能随时根据 UI 设计进度逐步替换。

## 5. 开发任务拆解

1. **数据模型更新 (Model)**
   - 修改 `Category` 模型，支持层级关系（可选：`parentId` 或新增 `CategoryGroup` 结构）。
   - 增加按点击频次/时间的记录逻辑，支撑“常用”Tab的数据计算。
2. **UI 组件重构 (View)**
   - 开发可横向滑动的 `CategoryTabBar` 组件。
   - 重构现有的分类网格视图 `CategoryGridView`，使其支持根据选中的 Tab 过滤数据。
   - 开发“全部”分类下的分组滑动视图。
3. **交互与状态 (ViewModel)**
   - 处理 Tab 切换与下方网格内容的联动逻辑。
   - 实现“常用”分类的动态计算逻辑。
