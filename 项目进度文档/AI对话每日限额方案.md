# AI 对话每日限额方案

> 版本：v2.1 临时方案  
> 状态：开发中  
> 更新时间：2026-05-23

---

## 一、背景

AI 对话功能依赖 LLM API（通义千问 qwen-plus），每次对话消耗 token 产生费用。为控制成本，在用户付费订阅体系上线前，采用每日免费次数限制作为过渡方案。

## 二、规则设计

| 项目 | 说明 |
|------|------|
| 每日免费次数 | **15 次/天** |
| 计数单位 | 每次 AI **成功响应**算 1 次（发送失败不扣） |
| 重置机制 | 每日 00:00 自动重置（基于本地日期） |
| 适用范围 | 所有 AI 交互：对话发送、图片 OCR、语音转文字后发送、快捷指令 OCR |

## 三、技术方案

### 3.1 存储方案：UserDefaults + 日期 Key

```
Key 格式: "ai_chat_usage_YYYY-MM-DD"
Value: Int（当日已用次数）
示例: "ai_chat_usage_2026-05-23" → 7
```

**为什么选 UserDefaults：**
- 零依赖，不需要新建 SwiftData 模型
- 日期 Key 天然"次日重置"，无需定时清理
- 后续删除干净，不留残留代码
- App 重启不丢失

**为什么不做防篡改：**
- 临时方案，用户清 UserDefaults 可绕过，可接受
- 正式订阅时接入服务端验证

### 3.2 计数时机

在 LLM API **成功返回结果后** +1，具体位置：

| 场景 | 触发位置 |
|------|----------|
| 文字对话 | `parseTransaction()` 成功返回后 |
| 图片 OCR | `processImage()` 中 OCR + 解析成功后 |
| 快捷指令 OCR | `processOCRText()` 解析成功后 |

**不扣次数的情况：**
- 用户发送消息但 LLM 返回错误
- 加载历史记录
- 取消入账操作

### 3.3 UI 反馈

#### 正常状态
- 输入栏下方显示 `今日剩余 X/15 次`，小字灰色
- 每次 AI 响应后实时更新

#### 达到上限
- 输入栏下方显示 `今日次数已用完，明天再来～`，红色提示
- 发送按钮禁用 + 变灰
- TextField placeholder 变为 `今日次数已用完`
- 快捷指令触发时返回提示文案

## 四、改动文件

| 文件 | 改动类型 | 内容 |
|------|----------|------|
| `Views/AIChatView.swift` | 功能新增 | 读取/写入计数，显示剩余次数，达限禁用输入 |
| `Views/MainTabView.swift` | 功能新增 | 快捷指令入口检查限额 |

**不需要新增文件**，UserDefaults 读写直接内联在 AIChatView 中（3-5 行工具代码）。

## 五、后续扩展路径

```
当前阶段：UserDefaults 本地计数（免费 15 次/天）
    ↓
会员订阅上线：UserDefaults → 读取订阅状态，订阅用户 unlimited
    ↓
正式版：接入服务端验证 + receipt 校验（防篡改）
```
