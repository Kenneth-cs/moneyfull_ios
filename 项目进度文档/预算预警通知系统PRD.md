**文档版本**：v1.1  
**创建日期**：2026-07-17  
**最后更新**：2026-07-17  
**功能归属**：Pro 功能 · 预算模块（需开通会员方可使用）

---

## 一、背景与目标

### 现状
目前预算预警只有**视觉提醒**（进度条变色、警告图标、数字变色），用户需要主动打开统计页才能感知超预算状态。

### 目标
补全「感知链路」的后半段：
- 用户记账时：**立即感知**（App 内弹窗）
- 用户离开 App 时：**被动触达**（系统推送）
- 用户长期不开 App：**定时唤回**（后台定时推送）

三个层次互补，覆盖用户所有使用状态。

---

## 二、核心概念定义

| 名词 | 定义 |
|------|------|
| **预警阈值** | 用户设置的首次提醒触发点，如 80% |
| **超出X%再次提醒（Step）** | 超过预警阈值后，每隔 X% 再提醒一次，默认 5%，用户可调整范围 1%~20% |
| **提醒检查点** | 每一个应该提醒的百分比节点，如设 80% 预警、步进 5% → 检查点为 80、85、90、95、100、105... |
| **当前检查点** | 当前已到达的最高检查点 |
| **总预算** | 项目整体预算（`project.budget`） |
| **分类预算** | 项目下某个具体分类的预算（`BudgetItem.amount`） |

## 三、功能一：App 内即时提醒（Banner / Sheet 混合）

### 3.1 触发时机

**触发点**：用户保存一条记账记录后，立即执行检查。

**检查对象**：
1. 该记账所属项目的**总预算进度**
2. 该记账所属**分类的预算进度**（若该分类有设置预算）

**触发条件**：任一对象的当前使用率，**跨越了一个新的检查点**。

### 3.2 检查点计算规则

```
检查点列表 = [预警阈值, 预警阈值+Step, 预警阈值+2×Step, ...]

示例：
  预警阈值 = 80%，Step = 5%
  检查点 = [80%, 85%, 90%, 95%, 100%, 105%, 110%...]

触发条件：
  上次提醒时的进度 < 某检查点 N
  && 本次保存后的进度 >= 检查点 N
  → 触发提醒，记录「当前检查点」为 N
```

### 3.3 提醒形式：Banner vs Sheet 混合方案

**根据同时触发的对象数量，选择不同的提醒形式**，轻重有别：

| 触发对象数量 | 提醒形式 | 说明 |
|------------|---------|------|
| **1 个**对象越过检查点 | **顶部 Banner**（Toast 样式，2 秒自动消失） | 非阻断，用户可继续操作，点击跳转预算详情 |
| **2 个及以上**对象同时触发 | **底部 Sheet**（需主动关闭） | 信息量多，需要用户关注，卡皮完整出场 |

**单触发 → 顶部 Banner 示意**：
```
┌──────────────────────────────────────────┐
│  🦫 「餐饮」预算已用到 85%，还剩 ¥150  › │  ← 点击跳详情
└──────────────────────────────────────────┘
（2 秒后自动消失，不打断记账流程）
```

**多触发 → 底部 Sheet 示意**：
```
┌──────────────────────────────────────┐
│  🦫  有几个预算需要注意一下            │
│                                      │
│  📊 总预算        ████████░░  85%   │
│  🍴 餐饮          ████████████ 90%  │
│  🚗 交通          ████████░░░  80%  │
│                                      │
│  "都在控制范围内，不慌，慢慢调 🍵"    │
│                                      │
│        [查看预算详情]    [知道了]      │
└──────────────────────────────────────┘
（需用户主动点击关闭）
```

### 3.4 状态持久化（防止重复提醒同一节点）

用 `UserDefaults` 存储每个预算对象已提醒过的最高检查点：

```
Key 格式：
  总预算：  budget_alert_project_{projectID}
  分类预算：budget_alert_category_{categoryID}

Value：
  已提醒的最高检查点百分比（Int），如 85
```

**重置时机**：
- 用户修改了预警阈值 → 重置该对象的记录
- 用户修改了总预算/分类预算金额 → 重置该对象的记录
- 预算周期刷新（如按月重置）→ 重置所有记录

### 3.5 卡皮情绪状态系统

弹窗内的卡皮 IP 形象与文案，根据进度分层展示：

| 当前进度 | 卡皮状态 | 表情描述 | 文案风格 |
|---------|---------|---------|---------|
| 首次越过阈值（如 80%） | 橘子微歪 🍊 | 微微惊讶但平静 | "有点超了，还在可控范围，没关系~" |
| 越过 100% | 橘子歪了 🍊💦 | 明显晃动 | "超预算啦，深呼吸，下个月调整回来就好" |
| 越过 120% | 泡进水里 🦫💦 | 整个沉下去 | "超了很多，要不要考虑调整一下预算呢？" |
| 越过 150% | 只剩头顶露出水面 | 佛系放弃状 | "钱嘛，乃身外之物。但还是记录一下比较好~" |

## 四、功能二：离开 App 后的系统推送通知

### 4.1 与 App 内即时提醒的核心区别

两者定位完全不同，**物理上互斥，永不同时出现**：

| 维度 | App 内即时提醒（Banner/Sheet）| 系统推送通知 |
|------|------------------------------|------------|
| **定位** | 「你刚才记账让预算发生了变化」| 「离开 App 后的一条冷静备忘」|
| **触发感** | 即时反馈，行为→结果 | 像股票预警，外部提醒 |
| **内容形式** | 有卡皮形象、进度条、颜色的 UI | 系统通知栏纯文字，简洁精准 |
| **出现时机** | 保存记账后**立刻**出现 | 记账保存后**延迟 5 分钟**，且用户已离开 App |
| **用户心理** | "啊，刚才记完这笔，超了" | "哦对，我之前超预算了，进去看看" |
| **行动路径** | 点击直接跳预算详情页 | 点击通知唤起 App 并跳预算详情页 |

**互斥机制（关键）**：
- 记账保存后，立即展示 App 内 Banner/Sheet
- 同时 schedule 一条系统推送（5 分钟后触发）
- 若用户在这 5 分钟内 App 仍在前台 → **取消该推送**，不重复提醒
- 若用户在 5 分钟内退出了 App → 推送正常发出

因此两者**物理上不会同时出现**，Banner 服务「在 App 内」的场景，推送服务「已离开 App」的场景。

### 4.2 触发与防抖规则

```
触发时机：记账保存后，检测到有对象越过检查点

防抖规则：
  - 同一个预算对象，5 分钟内多次触发，取消旧通知、只保留最新一条
  - 使用 Notification identifier = "budget_alert_{projectID}_{categoryID或total}"
  - 5 分钟内 App 回到前台 → 取消该 identifier 的推送
  - 5 分钟后没有新触发且 App 在后台 → 正式发出
```

### 4.3 推送文案设计（卡皮风格）

**单个超标**：
```
标题：🦫 小满提醒你
正文：「新疆游」的餐饮预算已用到 85%，还有 ¥150，出去吃别太放飞嗷~
```

**总预算超标**：
```
标题：🦫 小满提醒你
正文：「新疆游」总预算已用到 90%，还剩 ¥1000，稳住稳住 🍊
```

**多个同时超标（合并为一条）**：
```
标题：🦫 有 3 个预算需要注意
正文：「新疆游」餐饮 85%、交通 92%、总预算 88%，进来看看情况？
```

> 多个触发合并为一条通知，避免通知栏刷屏。

## 五、功能三：定时检查型推送（用户长期不开 App）

### 5.1 目标场景

用户几天没有打开 App，但后台数据显示某项目的预算即将/已经烧完。推送一条提醒，唤回用户来看看或调整计划。

### 5.2 检查策略

**检查频率**：每 24 小时检查一次（利用 iOS Background App Refresh 或提前 schedule 通知）

**检查内容**：遍历所有**进行中**的项目，找出符合条件的对象。

**触发条件**（满足其一即推送）：

| 条件 | 说明 |
|------|------|
| 总预算使用率 ≥ 预警阈值 | 已超过用户设置的预警线 |
| 总预算使用率 ≥ 90%（兜底） | 即使用户未设置预警，快烧完时仍提醒 |
| 总预算使用率 ≥ 100% | 已超预算 |

**不触发条件**：
- 用户在过去 24 小时内有记账行为（说明用户是活跃的，App 内弹窗已覆盖）
- 该项目预算为 0（未设置预算）
- 该项目已归档

### 5.3 多项目时的取值与优先级

**排序规则（从高到低优先级）**：

```
1. 已超预算（>100%）的项目，按超标比例降序
2. 使用率最高、且已过预警阈值的项目，按使用率降序
3. 使用率 ≥ 90% 但未设预警的项目
```

**通知数量策略**：
- **只发 1 条通知**，选取优先级最高的 1 个项目作为主体
- 若有多个项目超标，正文中补充「另有 N 个项目需关注」

**示例（多项目情况）**：
```
情景：
  - 「新疆游」总预算使用 105%（已超预算）
  - 「日常收支」总预算使用 92%（接近满额）
  - 「装修」总预算使用 45%（正常）

选取最紧急：「新疆游」作为主体

推送内容：
  标题：🦫 小满提醒你查看一下
  正文：「新疆游」预算已超标 5%，另有 1 个项目接近预算上限，进来看看？
```

### 5.4 推送频率控制（防骚扰）

> ⚠️ **重要说明**：以下 48 小时限制**仅适用于「定时检查型推送（本章第三层）」**，即用户长期不开 App 时的后台被动扫描推送。
>
> **记账行为触发的提醒（第一层 Banner/Sheet、第二层即时推送）不受此限制**，它们由「检查点系统」独立控制——同一检查点不重复提醒，但跨越不同检查点（80%→85%→90%）会正常多次提醒。

| 规则 | 设定 |
|------|------|
| 同一项目，同一状态，定时扫描推送间隔 | 48 小时（两天内同一项目不重复推被动扫描通知） |
| 用户 24 小时内有记账行为 | 跳过定时扫描推送（App 内已覆盖） |
| 用户关闭了通知权限 | 不发送 |

## 六、用户设置项

在**预算管理页 → 预算预警 Section**中新增以下设置：

| 设置项 | 类型 | 默认值 | 可调范围 | 说明 |
|------|------|--------|--------|------|
| 开启预算预警 | Toggle | 关 | — | 主开关，**Pro 会员专属** |
| 预警阈值 | Slider + Stepper 组合 | 80% | 50%~99%，步进 1% | 首次提醒触发点 |
| 超出X%再次提醒 | Slider + Stepper 组合 | 5% | 1%~20%，步进 1% | 越过阈值后每隔多少再提醒一次 |
| 离开 App 后推送 | Toggle | 开 | — | 控制记账触发的系统推送是否发出 |
| 长期不开 App 提醒 | Toggle | 开 | — | 定时检查型推送开关 |

**设置 UI 示意**：
```
[✓] 开启预算预警                         （Pro 专属，非会员显示锁定态）

    预警阈值
    ──────────────●──────  80%
                         [-]  80%  [+]    ← Slider 拖动 + 旁边 +/- 按钮，精确到 1%

    超出X%再次提醒
    ─────●───────────────  5%
                         [-]   5%  [+]

[✓] 离开 App 后也推送通知
[✓] 多天未开 App 时提醒我
```

> 预警阈值和步进均支持「Slider 拖动」快速调整 + 旁边「- / +」按钮精确微调，两者联动，同时生效，粒度均为 1%。

## 七、完整触发流程总图

```
用户保存记账
    │
    ▼
计算所有预算对象的进度变化（仅 Pro 会员执行）
    │
    ├─► 有对象越过检查点？
    │       │
    │       ├─ 是
    │       │    │
    │       │    ├─ 触发数 = 1 → 立即展示顶部 Banner（2s 自动消失）
    │       │    │
    │       │    └─ 触发数 ≥ 2 → 立即展示底部 Sheet（需主动关闭）
    │       │    │
    │       │    ▼
    │       │    Schedule 系统推送（identifier，5 分钟后触发）
    │       │    更新 UserDefaults 中的「当前检查点」
    │       │    │
    │       │    ├─ 5 分钟内 App 回到前台 → 取消推送（Banner 已覆盖）
    │       │    └─ 5 分钟后 App 仍在后台 → 推送正式发出
    │       │
    │       └─ 否 → 不做任何通知
    │
    └─► [后台定时，每 24h 一次]  ← 仅在第三层生效，与上方两层独立
            │
            ▼
        遍历进行中项目
            │
            ├─ 用户 24h 内有记账行为 → 跳过（前两层已覆盖）
            │
            └─ 找到符合条件的项目 → 取优先级最高项目 → 发推送
               （48h 内同一项目不重复，仅限本层被动扫描推送）
```

## 八、埋点需求

| 事件 | 说明 |
|------|------|
| `budget_alert_banner_shown` | 顶部 Banner 展示（单触发），附带 `category`、`progress` |
| `budget_alert_sheet_shown` | 底部 Sheet 展示（多触发），附带 `trigger_count` |
| `budget_alert_banner_tapped` | 点击 Banner 跳转预算详情 |
| `budget_alert_sheet_view_detail` | Sheet 内点击「查看预算详情」 |
| `budget_alert_sheet_dismiss` | Sheet 内点击「知道了」 |
| `budget_alert_push_scheduled` | 系统推送被 schedule |
| `budget_alert_push_cancelled` | 系统推送因用户回到前台被取消 |
| `budget_alert_push_opened` | 用户点击推送进入 App |
| `budget_alert_passive_shown` | 定时检查型推送展示 |
| `budget_alert_threshold_changed` | 用户修改「预警阈值」，附带 `new_value` |
| `budget_alert_step_changed` | 用户修改「超出X%再次提醒」值，附带 `new_value` |

## 九、开发优先级建议

| 阶段 | 内容 | 复杂度 |
|------|------|--------|
| **P0（先做）** | App 内即时弹窗（单/合并）+ 检查点逻辑 + UserDefaults 状态持久化 | 中 |

## 十、未解决的问题（待决策）

1. **iOS 后台刷新限制**：iOS 不保证 Background App Refresh 准时执行，定时检查型推送可能需要在用户每次打开 App 时重新 schedule 未来的推送通知（预先 schedule 未来 7 天的时间触发器）。方案：可以的
2. **分类预算的「超出X%再次提醒」是否与总预算共用同一个 Step 设置？** 方案：先按共用方案，后续再按需要看是否需要为分类单独设置
3. **预算周期为「按月刷新」的项目，月初重置后，上月已记录的提醒检查点如何处理？** 方案：随预算周期重置时一并清除。
