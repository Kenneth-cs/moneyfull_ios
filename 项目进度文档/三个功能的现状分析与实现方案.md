#### 2.2 智能评分弹窗设计

创建一个自定义评分弹窗组件 `AppRatingPrompt`：

**触发条件（全部满足才弹出 — AND 逻辑）：**

| 条件 | 说明 | UserDefaults Key | 判断逻辑 |
|------|------|------------------|----------|
| 使用 ≥ 7 天 | 确保用户是长期用户 | `firstLaunchDate` | `daysSinceFirstLaunch >= 7` |
| 记账 ≥ 15 笔 | 确保用户有实际使用体验 | 通过 `modelContext.fetchCount()` 查询真实总数 | `transactionCount >= 15` |
| 未评过分 | 避免重复打扰已评分用户 | `hasRatedApp == false` | `hasRatedApp == false` |
| 拒绝次数 < 3 | 用户没有明确拒绝过 | `ratingDismissCount < 3` | `ratingDismissCount < 3` |
| 冷却期 ≥ 14 天 | 避免频繁弹出 | `lastRatingPromptDate` | `daysSinceLastPrompt >= 14` |

**为什么用 AND 逻辑而不是 OR？**
- 如果只用 OR：用户可能只用了1天但记了15笔账，就弹评分弹窗，体验很差
- 用 AND：确保用户是真正活跃、有良好体验后才弹出，提高好评率

#### 2.3 触发时机与逻辑

在 `ContentView.swift` 的 `.onAppear` 中检查条件：

```swift
// AppRatingManager.swift 核心逻辑
class AppRatingManager {
    static let shared = AppRatingManager()
    
    func shouldShowRating(transactionCount: Int) -> Bool {
        // 1. 已评分，不再弹
        if UserDefaults.standard.bool(forKey: "hasRatedApp") {
            return false
        }
        
        // 2. 拒绝次数过多（3次），不再弹
        if UserDefaults.standard.integer(forKey: "ratingDismissCount") >= 3 {
            return false
        }
        
        // 3. 使用天数不足（< 7天）
        guard let firstLaunch = UserDefaults.standard.object(forKey: "firstLaunchDate") as? Date else {
            return false
        }
        let daysSinceLaunch = Calendar.current.dateComponents([.day], from: firstLaunch, to: Date()).day ?? 0
        if daysSinceLaunch < 7 {
            return false
        }
        
        // 4. 记账笔数不足（< 15笔）
        if transactionCount < 15 {
            return false
        }
        
        // 5. 冷却期检查（< 14天）
        if let lastPrompt = UserDefaults.standard.object(forKey: "lastRatingPromptDate") as? Date {
            let daysSinceLastPrompt = Calendar.current.dateComponents([.day], from: lastPrompt, to: Date()).day ?? 0
            if daysSinceLastPrompt < 14 {
                return false
            }
        }
        
        return true
    }
}
```

在 ContentView 中调用：

```swift
// ContentView.swift
.onAppear {
    // ... 其他逻辑
    
    // 检查是否需要弹出评分弹窗
    if AppRatingManager.shared.shouldShowRating(transactionCount: store?.recentTransactions.count ?? 0) {
        DispatchQueue.main.asyncAfter(deadline: .now() + 2.0) {
            showRatingPrompt = true
        }
    }
}
```

#### 3.4 通知注册/取消逻辑

```
开启提醒时:
  1. 检查通知权限 → 如果未授权，引导去系统设置
  2. 创建 UNCalendarNotificationTrigger（指定 hour/minute）
  3. 注册 UNNotificationRequest（identifier: "daily_reminder"）
  4. 保存设置到 UserDefaults

关闭提醒时:
  1. 移除 pending notification (identifier: "daily_reminder")
  2. 保存设置到 UserDefaults

修改时间时:
  1. 先移除旧的
  2. 按新时间重新注册
```

#### 3.6 周末免打扰

```
逻辑: 
  - 如果开启「休息日免打扰」
  - 判断今天是否为周六/周日
  - 如果是，跳过当天通知，改为明天同一时间
  - 使用 UNCalendarNotificationTrigger 的 repeats + 自定义 DateComponents
  
实现方案:
  方案A: 每天都注册通知，在通知内容中动态判断（通过 Notification Extension 或 UNUserNotificationCenterDelegate 在展示前过滤）
  方案B: 只注册工作日的通知，每次 app 启动时重新计算并注册未来的通知

推荐使用方案A，实现更简洁，不需要每次启动都重新计算。
```
