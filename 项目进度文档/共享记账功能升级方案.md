## 一、核心设计原则（不变）

| | 原方案（已建） | 本次升级 |
|--|--|--|
| 入口 | 独立的"共享账本"入口 | 整合进现有项目列表 ✅ |
| 项目模型 | 单人项目和共享账本是两个概念 | 统一为"项目"，区别只是是否有成员 ✅ |
| 记账流程 | 共享账本独立记账 UI | 复用现有"记一笔"，共享项目条件展示额外字段 ✅ |
| 成员加入 | 创建时预填成员信息 | 邀请码/二维码/链接分享，对方填昵称加入 ✅ |

**项目类型定义（已实现）：**

```
个人项目  = 成员只有自己，数据存 SwiftData + iCloud（现有逻辑不变）
共享项目  = 成员 ≥ 2 人，数据存服务器（mf_shared_* 表）
```

## 三、数据显示规则（与 v1.0 一致）

### 3.1 共享项目流水展示

所有流水对全体成员透明可见：

```
🍜 拉面                         ¥268
Tim 支付 · 3人参与

🏪 便利店                       ¥36
A 支付 · 仅A参与                 ← B 没参与时标注
```

> B 能看到"仅A参与"的流水，但不计入 B 的个人消费统计。

### 3.2 成员统计规则

| 指标 | 计算规则 |
|------|---------|
| **付了多少钱** | `payer_name = 该成员` 的流水金额之和 |
| **消费了多少** | 该成员在 `participants` 中的流水，按人数平均分摊之和 |
| **净差值**（V2） | 付款 - 消费，正数应收、负数应付 |

V1 只展示"我支付 ¥X / 小美支付 ¥X / Tim 支付 ¥X"，AA 结算放 V2。

### 3.3 首页总支出规则

**V1：首页总支出只统计个人项目，共享项目数据不混入**

原因：V1 无 AA 结算，把垫付金额计入个人支出会严重失真。

首页横滑卡片同时显示个人项目（标签"个人"）和共享项目（标签"👥 共享·N人"）。

## 五、数据库变更（后端，待执行）

在已建的 `mf_shared_transactions` 表新增 3 个字段：

```sql
ALTER TABLE mf_shared_transactions
  ADD COLUMN payer_name   VARCHAR(50)  NULL AFTER participant_name,
  ADD COLUMN participants JSON         NULL AFTER payer_name,
  ADD COLUMN split_method VARCHAR(20)  NOT NULL DEFAULT 'equal' AFTER participants;

-- payer_name:   付款人昵称，与记账人（participant_name）可不同
--               NULL 时降级展示为 participant_name（向后兼容旧数据）
-- participants: 参与人昵称列表，如 ["Tim", "小美", "阿杰"]
--               NULL 时视为全体成员参与
-- split_method: V1 固定 'equal'，V2 新增 'custom'
```

其余三张表结构不变。

## 六、API 变更（后端，待开发）

### 6.1 写入流水接口（已有，扩展字段）

```
POST /shared-projects/:inviteCode/transactions

Body（新增三个可选字段，向后兼容）：
{
  "deviceId": "ABC123",
  "transactions": [
    {
      "id": "uuid",
      "amount": 268.00,
      "category": "餐饮",
      "note": "拉面",
      "transactionAt": "2024-10-03T12:00:00Z",
      "payerName": "Tim",                          // 新增
      "participants": ["Tim", "小美", "阿杰"],       // 新增
      "splitMethod": "equal"                        // 新增
    }
  ]
}
```

服务端 `INSERT` 语句加入三个字段即可，旧客户端不传时三字段为 NULL。

### 6.2 拉取流水接口（已有，扩展返回）

```
GET /shared-projects/:inviteCode/transactions?since=...

Response（新增字段，旧客户端忽略）：
{
  "transactions": [
    {
      "id": "...",
      "participantName": "Tim",       // 记账人（原有）
      "payerName": "Tim",             // 付款人（新增）
      "participants": ["Tim","小美"],  // 参与人（新增）
      "splitMethod": "equal",          // 分摊方式（新增）
      "amount": -268.00,
      "category": "餐饮",
      "note": "拉面",
      "transactionAt": "...",
      "isDeleted": false,
      "serverUpdatedAt": "..."
    }
  ],
  "serverTime": "..."
}
```

### 6.3 获取成员统计接口（新增）

```
GET /shared-projects/:inviteCode/stats

Response 200:
{
  "totalAmount": 8560.00,
  "memberStats": [
    {
      "participantName": "Tim",
      "deviceId": "ABC123",
      "totalPaid": 3260.00,        // payer_name = Tim 的流水之和
      "totalConsumed": 2860.00     // participants 含 Tim 的流水按人数平摊后之和
    },
    {
      "participantName": "小美",
      "deviceId": "DEF456",
      "totalPaid": 1800.00,
      "totalConsumed": 2850.00
    }
  ]
}
```

> V1 服务端聚合计算，避免客户端下载全量数据再本地运算。
> 计算逻辑：`totalPaid = SUM(amount) WHERE payer_name = name AND is_deleted = 0`
> `totalConsumed = SUM(amount / JSON_LENGTH(participants)) WHERE JSON_CONTAINS(participants, '"name"') AND is_deleted = 0`

### 6.4 获取项目详情接口（新增，用于加入前预览）

```
GET /shared-projects/:inviteCode/info

Response 200:
{
  "projectId": "...",
  "name": "日本旅行",
  "memberCount": 2,
  "members": [
    { "participantName": "Tim", "joinedAt": "..." },
    { "participantName": "小美", "joinedAt": "..." }
  ],
  "createdAt": "..."
}

Response 404:
{ "error": "invite_code_not_found" }
```

> 加入确认页需要先展示"项目名 + 已有成员"，所以需要这个接口。
