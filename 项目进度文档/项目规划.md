# 项目记账 App 设计文档

> **一切皆项目的个人记账 app——不只记流水，更追踪每一件事的花费全貌。**

## 1. 产品定位

### 核心洞察

类目告诉你「钱花在什么类型上」，但项目告诉你「钱花在什么事情上」。一个是会计视角，一个是生活视角。传统记账 app 永远回答不了「我为这个女生一共花了多少钱」这种问题。

### 一句话定位

一切皆项目的个人记账 app——不只记流水，更追踪每一件事的花费全貌。

### 核心概念

- 所有消费都属于某个「项目」，项目是第一公民
- 系统内置一个**「日常生活」默认项目**，永远置顶、不可删除，承接所有零散消费
- 用户可随时创建新项目（搬家、旅行、约会……），也可随时归档已完成的项目
- 每笔消费 = **必选类目 + 所属项目（默认日常生活）**
- 类目分为**通用类目**（系统预设：餐饮、交通、购物、娱乐、住房等）和**自定义类目**（随用随加，无需提前定义）

## 2. 目标用户

### MVP 聚焦人群

**已经有记账习惯，但觉得「记了也看不出什么」的年轻人（22-35 岁）**

用户画像特征：
- 正在使用或曾经使用过小青账、鲨鱼记账等 app
- 每月记账但总觉得「钱不知道花哪了」——类目饼图看不出生活中具体事件的花费
- 生活中有明确的「事件」或「活动」：旅行、搬家、约会、筹备婚礼、做副业等
- 有一定的复盘意识，喜欢掌控感

### 为什么聚焦这群人

1. 不需要教育「为什么要记账」，只需要告诉他们「你缺一个维度」
2. 从现有记账 app 迁移，比从零培养习惯容易得多
3. 社交分享意愿较强（小红书、即刻上大量记账分享内容）

### 未来拓展方向

- 情侣/家庭共享记账
- 自由职业者/小创业者按项目追踪成本和利润

## 3. 市场与规模

- 中国移动记账用户约 3000-5000 万
- 对记账有进阶需求、愿意尝试新工具的用户约 5-10%（150-500 万潜在用户）
- 独立开发者只需抓住其中 1%（1.5-5 万付费用户），乘以 ¥38 买断即可实现可观收入
- **定位：小而美的精准工具，不需要做大市场**

## 4. 平台与技术栈

| 维度 | 选择 | 理由 |
|------|------|------|
| 平台 | iOS 优先 | 目标用户集中，App Store 付费意愿更高 |
| UI 框架 | SwiftUI | Apple 最新框架，声明式语法，AI 辅助编程效果最好 |
| 数据存储 | SwiftData（纯本地） | MVP 阶段最简单，无需后端成本 |
| 未来同步 | iCloud / 自建云端（待定） | 达到信心线后再决定方案 |

## 5. App 结构

### Tab 栏（4 个）

| Tab | 图标 | 名称 | 功能 |
|-----|------|------|------|
| 1 | 📋 | 项目 | 首页。项目卡片列表，「日常生活」置顶，分「进行中」和「已归档」两个区域 |
| 2 | 📊 | 统计 | 双维度切换：按类目（传统饼图/条形图）和按项目（项目花费排行） |
| 3 | ➕ | 记一笔 | 核心记账入口，默认归入「日常生活」 |
| 4 | 👤 | 我的 | 设置、升级 Pro、通用类目管理、数据导出、提醒设置 |

### 项目首页（Tab 1）

- **「日常生活」卡片**永远置顶，带「默认」标签，显示本月总支出和前 2-3 个类目标签
- **进行中项目**区域：按最近活跃排序，每张卡片显示：
  - Emoji 图标 + 项目名称
  - 累计总金额
  - 子类目标签（前 2-3 个 + 「+N」折叠）
  - 开始日期、消费笔数、状态
- **已归档项目**区域：视觉上降低透明度，点击可查看但不可新增消费
- 项目卡片点击进入**项目详情页**

### 项目详情页

- 项目总金额 + 类目占比饼图
- 该项目下的消费流水时间线
- 项目专属类目管理（可在此添加自定义类目）

### 记一笔流程（Tab 3）

3 步零摩擦：

1. **输入金额 + 选类目**——顶部显示当前项目（默认「日常生活」），下方显示类目选择（通用 + 自定义 + 「新增」按钮）
2. **切换项目（可选）**——点击顶部项目名可切换，显示最近项目列表，一键关联。不点就默认归入「日常生活」
3. **保存完成**

设计要点：
- 绝大多数日常消费无需选项目，实现零额外操作
- 只有需要归到特定项目时才多一步切换
- 支持记录收入和支出两种类型

### 统计页（Tab 2）

顶部 Segmented Control 切换两种视角：

**按类目视角（传统）：**
- 月度总支出金额
- 各类目的金额和占比（条形图/饼图）
- 支持按月切换查看趋势

**按项目视角（差异化）：**
- 各项目本月花费排行
- 项目累计总花费排行

### 我的页（Tab 4）

- 通用类目管理（增删改排序）
- 升级 Pro（显示价格和功能对比）
- 数据导出（Pro 功能）
- 记账提醒设置
- 关于

## 6. 数据模型

### 核心实体

**项目（Project）：**
- id: UUID
- name: String（项目名称）
- emoji: String（图标）
- isDefault: Bool（是否为「日常生活」默认项目）
- status: Enum（进行中 / 已归档）
- createdAt: Date
- archivedAt: Date?（归档时间）

**类目（Category）：**
- id: UUID
- name: String（类目名称）
- emoji: String（图标）
- isSystem: Bool（是否系统预设）
- createdAt: Date

**消费记录（Transaction）：**
- id: UUID
- amount: Decimal（金额）
- type: Enum（支出 / 收入）
- note: String?（备注）
- date: Date（消费日期）
- createdAt: Date
- project: Project（所属项目，必选）
- category: Category（所属类目，必选）

### 关系

- 一个 Project 有多个 Transaction（一对多）
- 一个 Category 有多个 Transaction（一对多）
- 一笔 Transaction 同时属于一个 Project 和一个 Category（双重归属，互不冲突）
- 类目是全局共享的，不按项目隔离——同一个「餐饮」类目可出现在多个项目中
- 用户可在任何场景下随时新增自定义类目

### 系统预设类目

餐饮、交通、购物、娱乐、住房、医疗、教育、通讯、服饰、日用、其他

## 7. 商业模式

### 三层阶梯：免费 + Pro 买断 + Premium 订阅

| 层级 | 价格 | 功能 |
|------|------|------|
| 🆓 免费 | ¥0 | 完整记账功能、通用类目、自定义类目、最多 3 个项目（不含「日常生活」）、基础月度报表 |
| 💎 Pro | ¥38 一次性买断 | 无限项目、完整统计报表（按类目 + 按项目）、数据导出 CSV |
| 🚀 Premium | ¥68/年 订阅 | Pro 全部功能 + 多设备同步（未来）、AI 智能分析（未来）、家庭/情侣共享（未来） |

### 设计理由

- 记账类 app 用户对订阅敏感，纯订阅会劝退大量用户
- 买断制决策成本低（¥38），适合快速验证付费意愿
- 订阅制留给**有持续成本的增值服务**（同步、AI、共享），用户更容易接受
- 免费层提供 3 个项目上限，足够让用户体验核心价值，又能在项目数增长后触发付费转化

### MVP 阶段商业模式

- 只实现免费层 + Pro 买断
- Premium 订阅在后续迭代中推出

## 8. 视觉风格

- **简洁克制**：专注效率，无花哨装饰，参考小青账的清爽风格
- **活力配色**：不是黑白灰的冷淡风，使用鲜明但不刺眼的主色调，让页面有生气
- **AI 友好的设计系统**：使用 SwiftUI 原生组件和 SF Symbols 图标，避免需要手绘的定制化 UI
- **项目卡片**：使用 Emoji 作为项目图标（用户选择），辨识度高，零设计成本

## 9. MVP 范围

### 包含（Must Have）

- ✅ 项目列表首页（含「日常生活」默认项目）

- ✅ 记一笔（金额 + 类目 + 项目，支持收入/支出）
- ✅ 通用类目预设 + 自定义类目随时加

- ✅ 本地存储（SwiftData）

## 10. 成功标准

### 前提条件

指标判断需要有效样本量：至少积累 **500+ 下载、50+ 周活跃用户** 再看量化指标。在此之前重点看**定性反馈**——找 10-20 个真实用户访谈，了解他们用不用项目功能、为什么用/不用。

### 两条线

| 指标 | 📛 生死线（低于就停下来反思） | 🟢 信心线（达到就加大投入） |
|------|------|------|
| 7 日留存 | < 20% | ≥ 35% |
| Pro 付费转化率 | < 1% | ≥ 5% |
| 用户反馈 | 无人主动提到「项目」功能 | 有用户因「项目」功能给好评或分享 |

### 如何行动

- 📛 **两个指标都低于生死线** → 核心假设可能错了。暂停推广，做用户访谈，搞清楚是「没人需要项目记账」还是「产品没做好」
- 🟡 **介于两条线之间** → 方向对但需要打磨。分析用户行为，优化记账流程和项目体验，小步迭代
- 🟢 **达到或超过信心线** → 验证成功！开始投入推广预算，启动 V2 规划

### 第一阶段目标（上线后 3 个月）

| 指标 | 目标 |
|------|------|
| 下载量 | 1,000 - 3,000 |
| 7 日留存率 | ≥ 30% |
| Pro 付费转化率 | ≥ 3% |
| App Store 评分 | ≥ 4.5 |

## 11. 推广策略

### 核心原则

零预算冷启动 → 验证后再投入。

### 阶段一：上线前（1-2 周预热）

| 渠道 | 做什么 |
|------|------|
| 小红书 | 发 1 篇痛点共鸣帖：「记了三年账，还是不知道钱花哪了」——讲真实故事，不提 app |
| 即刻 | 在产品经理、独立开发圈子发帖，讲「项目记账」的思路，收集早期种子用户 |
| 朋友圈 | 招 20-30 个朋友做内测，收集真实反馈 |

### 阶段二：上线后第 1 个月（自然增长）

| 渠道 | 做什么 |
|------|------|
| App Store ASO | 关键词优化：「记账」「项目记账」「旅行记账」「装修记账」「搬家花费」 |
| 小红书 | 产品发布帖 +真实数据帖（用自己的 app 记两周账后分享发现）|
| V2EX | 发到 create 节点，独立开发者社区对新工具友好 |
| App 内 | 记账满 7 天后引导好评（最多弹一次）|

### 阶段三：达到信心线后（付费推广）

| 渠道 | 预算 |
|------|------|
| 小红书信息流 | 先投 ¥500 测试 CPA |
| Apple Search Ads | ¥1,000 起测，竞价记账相关关键词 |
| KOL 合作 | 找记账/理财类小博主（1-5 万粉），置换或小额合作 |

### 内容计划（共 4 篇，不需要日更）

| 时间 | 内容 | 平台 |
|------|------|------|
| 上线前 1 周 | 痛点共鸣：「记了三年账，还是不知道钱花哪了」 | 小红书、即刻 |
| 上线当天 | 产品发布：「所以我自己做了一个 app」 | 小红书、即刻、V2EX |
| 上线 2 周后 | 真实数据：「用自己的 app 记了两周账，发现…」 | 小红书 |
| 上线 1 月后 | 开发复盘：「独立开发一个月，下载 XX，收入 XX」 | 即刻、V2EX |
