## 一、编辑账单页字段对齐（EditTransactionView）

### 问题描述

`EditTransactionView`（所有账单列表点击"编辑"后进入的页面）与`AddRecordView`（记一笔）字段严重不对齐：

| 字段 | 记一笔 | 编辑账单 |
|------|--------|----------|
| 日期 | ✅ 悬浮胶囊，金额区左上角显示 | ❌ 藏在数字键盘 calendar 键里 |
| 归属项目 | ✅ 横向卡片滑动选择 | ❌ 完全缺失 |
| 分类 | ✅ Tab 分组 + 网格（带"常用"等分组） | ⚠️ 简陋 LazyVGrid，无分组 |
| 备注 | ✅ | ✅ |

### 改动目标

让编辑账单页与记一笔页**一模一样**，用户不会因为两个入口体验割裂而困惑。

### 技术方案

**方案：复用 AddRecordView 的 UI 结构，而非单独维护一套**

将核心表单区域提炼为一个独立的共享组件 `TransactionFormView`，同时接收"新建"和"编辑"两种模式：

```swift
struct TransactionFormView: View {
    @Binding var type: TransactionType
    @Binding var amount: String
    @Binding var selectedCategory: Category?
    @Binding var selectedProject: Project?
    @Binding var note: String
    @Binding var date: Date
    // ...
}
```

`AddRecordView` 和 `EditTransactionView` 都嵌入这个组件，差异仅在标题和保存逻辑上。

**具体需要改动的文件：**

- `moneyfull_ios/Views/EditTransactionView.swift`
  - 增加 `@State private var selectedProject: Project?`
  - `init` 中从 `transaction.project` 读取初始项目
  - 在 ScrollView 中，金额区下方插入与 AddRecordView 完全一致的"归属项目"横向卡片 UI
  - 将日期按钮从数字键盘移到金额区左上角悬浮胶囊（与 AddRecordView 一致）
  - 分类选择改为使用 `CategorySelectionView`（带 Tab 分组），替换现有 LazyVGrid
  - `handleSave()` 中同步更新 `transaction.project`（目前 `AppStore.updateTransaction` 没有 project 参数，需一并补充）

- `moneyfull_ios/Models/AppStore.swift`
  - `updateTransaction` 增加 `project: Project?` 参数，保存时同步修改 `tx.project`

**入口说明（目前两处使用 EditTransactionView，均需验证）：**
- `DashboardView.swift` 第 207 行
- `ProjectDetailView.swift` 第 220 行

## 二、AI 对话页账单卡片功能完善

### 问题描述

1. AI 识别到账单后，交易确认卡片**缺少项目归属的显示和修改控件**，用户无法在确认前指定归属项目
2. 入账成功后，AI 气泡仅追加一行文字"已成功入账"，**没有提供修改和删除的操作按钮**（参考竞品图3：有"修改账单"和"删除账单"两个胶囊按钮）

### 改动目标

- 交易确认卡片新增项目选择行（可交互）
- 入账成功后气泡下方出现"修改账单"和"删除账单"两个按钮
- 点击"修改账单"跳转到 `EditTransactionView`
- 点击"删除账单"直接删除，并在气泡上显示已删除状态

### 技术方案

#### 2.1 确认卡片新增项目选择

在 `TransactionCardData` 中增加可变的项目选择状态（注意卡片当前是值类型，需要改为支持用户交互的方式）：

**`CommonViews.swift` 中的 `TransactionConfirmCard`：**
- 新增一行"归属项目"，展示当前项目名（来自 `cardData.projectName`）
- 右侧放一个"更改"按钮，点击弹出项目选择 Sheet（横向卡片，与记一笔一致）
- 将用户选择的项目名回传给 `AIChatView` 的确认回调

**数据流调整：**

目前 `onConfirm` 回调签名为 `(TransactionCardData) -> Void`，需要支持把用户修改后的项目名带回去。可在 `AIChatView` 里用 `@State` 维护一个 `selectedProjectOverride: String?`，确认时优先使用用户选择的项目名。

#### 2.2 入账成功后的操作按钮

**核心问题：** 目前 `handleTransactionConfirmed` 只追加了一条文字消息，没有保存入账后的 `Transaction` 对象引用，导致后续无法对它进行修改或删除。

**修复方案：**

1. 在 `handleTransactionConfirmed` 中，调用 `store.addTransaction` 并**保存返回的 `Transaction` 对象引用**（需要 `addTransaction` 有返回值，目前是 `void`，需改为 `@discardableResult func addTransaction(...) -> Transaction`）

2. `ChatMessage` 增加一个 `confirmedTransaction: Transaction?` 字段，用于绑定已入账的交易对象

3. 成功入账后追加的 `ChatMessage` 携带 `confirmedTransaction`，在 `ChatBubble` 的渲染逻辑中，当检测到 `confirmedTransaction != nil` 时，在气泡下方渲染两个胶囊按钮：

```
[修改账单]  [删除账单]
```

- 点击"修改账单"：`sheet(item:)` 弹出 `EditTransactionView`，传入对应的 `Transaction`
- 点击"删除账单"：调用 `store.deleteTransaction`，更新该条消息的显示文本为"已删除"，隐藏按钮

**需要改动的文件：**
- `moneyfull_ios/Views/AIChatView.swift`：`ChatMessage` 增加字段，`handleTransactionConfirmed` 补充逻辑，`ChatBubble` 增加操作按钮渲染，新增 `@State private var editingTransaction: Transaction?` + `.sheet`
- `moneyfull_ios/Components/CommonViews.swift`：`TransactionConfirmCard` 增加项目选择行
- `moneyfull_ios/Models/AppStore.swift`：`addTransaction` 改为有返回值

## 三、AI 对话历史持久化

### 问题描述

`AIChatView.swift` 第 398 行 `loadChatHistory()` 是**空函数**，数据虽然通过 `saveChatHistory` 写入了 SwiftData（并随 iCloud 同步），但读取逻辑没有实现，导致每次进入页面对话记录都清空。

### 改动目标

- 进入 AI 对话页时，从 SwiftData 恢复历史对话记录
- 对话记录通过 iCloud（已配置 CloudKit）自动跨设备同步
- 合理控制加载条数（避免一次加载几千条历史）

### 技术方案

#### 3.1 ChatHistory 与 ChatMessage 的映射

SwiftData 存储的是 `ChatHistory`（持久化对象），页面展示的是 `ChatMessage`（UI 值类型）。`ChatHistory.content` 目前存的是：
- 普通文本消息：原始文本
- 交易确认卡片：硬编码字符串 `"交易确认卡片"`
- 新分类建议：`"新分类建议卡片"`

**历史记录恢复策略：** 仅恢复可以直接展示的文本类型消息（`role = user` 或普通 `assistant` 文本），卡片类消息因为缺失结构化数据，历史展示时退化为纯文本（即原来 `saveChatHistory` 存的那句话）。

这在工程上是最简单且安全的做法，不需要把整个 `TransactionCardData` 序列化存储。

#### 3.2 loadChatHistory 实现

```swift
private func loadChatHistory() {
    guard let context = contextManager.modelContext else { return }
    let descriptor = FetchDescriptor<ChatHistory>(
        sortBy: [SortDescriptor(\.timestamp, order: .forward)]
    )
    // 只加载最近 50 条，避免历史过长
    var limitedDescriptor = descriptor
    limitedDescriptor.fetchLimit = 50
    
    let histories = (try? context.fetch(limitedDescriptor)) ?? []
    messages = histories.map { history in
        ChatMessage(
            role: history.role == "user" ? .user : .assistant,
            content: history.content,
            timestamp: history.timestamp
        )
    }
}
```

同时需要在 `ContextManager` 里将 `modelContext` 的访问级别从 `private` 改为 `internal`，或者提供一个 `fetchChatHistory(limit:) -> [ChatHistory]` 的公共方法。

#### 3.3 iCloud 同步

`ChatHistory` 已在 `ModelContainer` 中注册（`moneyfull_iosApp.swift` 第 19 行），且 CloudKit 配置为 `.automatic`，所以**不需要额外工作**，历史记录已随 iCloud 自动同步。

## 实施优先级

| 优先级 | 模块 | 原因 |
|--------|------|------|
| P0 | 二（入账后修改/删除按钮） | 影响核心记账操作，用户无法纠错 |
| P0 | 三（对话历史持久化） | 逻辑已完成一半，改动最小，价值最高 |
| P1 | 一（EditTransactionView 字段对齐） | 体验一致性，改动面稍大 |
| P1 | 二（确认卡片项目选择） | 依赖 EditTransactionView 的项目选择组件 |
