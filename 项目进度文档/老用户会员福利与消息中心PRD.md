## 一、背景与目标

钱小满即将上线会员付费服务。为了保护"从免费时代就陪伴我们"的老用户体感，决定：

1. **给老用户送 6 个月「高级会员」免费体验期**（无门槛自动到账，到期不自动扣费）。
2. 用一封**感谢信**的形式告知老用户这个决定，信的内容已经写好（见附录）。
3. 这封信需要：
   - 老用户升级到新版本、**打开 App 时自动弹出一次**；
   - 关掉之后，**还能在"消息中心"里再翻出来看**（首页右上角铃铛入口，目前是占位图标，本次一起补上列表功能）；
   - 在**订阅详情页**放一个入口链接，点开看的是同一份内容。

本 PRD 覆盖以上 4 件事的完整方案：① 老用户判定与会员发放逻辑　② 感谢信弹窗　③ 消息中心　④ 订阅页入口。

### 1.1 老用户定义

> 2026年7月18日（老用户判定截止日期）往前，**本机 / 本 iCloud 账号下存在至少一条记账记录**的用户。
> 
> **领取截止时间**：2026年9月18日（2个月窗口期），之后不再发放福利。

### 1.2 名词说明

| 名词 | 说明 |
|------|------|
| 老用户福利 / Legacy Gift | 给老用户自动赠送的 6 个月会员体验期，**不经过苹果内购，是纯本地软件层面的"放行"**，不会真实扣款 |
| 感谢信 | 本次要发的那封长文，标题"给陪伴的你" |
| 消息中心 | 首页铃铛点开后的列表页，未来其他公告也会放在这里，本次是第一次做这个功能 |
| 老用户判定截止日期 | 2026-07-18，此日期前有记账记录的用户才算老用户 |
| 福利领取截止日期 | 2026-09-18，此日期后不再发放福利（2个月窗口期） |

## 二、现状盘点（决定技术方案的关键事实）

在动手之前，先说清楚现在代码里已经有什么、没有什么，这决定了下面方案怎么设计最省事：

1. **会员状态判断**：全项目 10+ 个页面都是直接读 `StoreManager.isPremium` 这一个字段（`@Published var isPremium: Bool`），它目前只由"苹果真实订阅验证结果"决定。→ 我们要做的是**在这一个字段的计算方式里加一条"或者本地赠送期还没到期"**，其余页面不用改。
2. **数据同步**：项目已经用 SwiftData + CloudKit 私有数据库自动同步账本数据（`moneyfull_iosApp.swift` 里 `ModelConfiguration(cloudKitDatabase: .automatic)`）。→ **赠送记录和消息列表的"已读"状态，都应该存成 SwiftData 模型**（不是 UserDefaults），这样能免费获得"换设备也不丢"的能力，不需要额外接入别的同步机制。
3. **首页铃铛**：`Components/CommonViews.swift` 里的 `PageHeader` 组件右上角已经放了一个 `bell` 图标，但**目前没有点击事件、没有角标、也没有列表页**，是纯装饰占位。→ 消息中心是从零建的新功能，不是"补全现有页面"。
4. **老用户判断的触发时机**：`ContentView.swift` 里 `AppStore.initialize()` 已经有一个几乎一样的"一次性检测"先例（Grandfathering：检测老用户项目数是否超限），本次直接复用同一种"一次性 flag 保护"的写法。
5. **长文排版**：`ArticleDetailView.swift` 已经有一套"按 `##` `•` `💡` `⚠️` 前缀渲染标题/列表/提示"的段落解析逻辑，本次感谢信的正文直接复用这套逻辑，不用重新发明。

## 三、功能一：老用户判定 与 会员福利发放

### 3.1 判定规则

App 每次启动，在 `AppStore.initialize()` 里，增加一次性检测（仅执行一次，用 flag 保护，和 Grandfathering 检测写在一起）：

```
若 legacyGiftChecked == false：
    查询 SwiftData：是否存在一条 Transaction，其 date/createdAt 早于「老用户截止日期常量」（2026-07-18）
    若存在 且 尚未领取过 且 当前日期早于「领取截止日期常量」（2026-09-18）：
        创建 LegacyGiftGrant 记录：isGranted = true，grantedAt = 今天，expiresAt = 今天 + 6 个月
        在消息中心插入一条"给陪伴的你"通知（未读）
        标记 legacyGiftChecked = true，本次会触发一次弹窗
    否则：
        仅标记 legacyGiftChecked = true，不弹窗
```

> **关键常量**：
> - `legacyUserCutoffDate = 2026-07-18`：老用户判定截止日期，7月18日之前有记账记录的用户才算老用户
> - `legacyGiftClaimDeadline = 2026-09-18`：福利领取截止日期，9月18日之后不再发放福利（2个月窗口期）

### 3.2 数据模型：`LegacyGiftGrant`（新增 SwiftData 模型）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| isGranted | Bool | 是否已发放（全局只会有一条记录，发放后不会撤销） |
| grantedAt | Date? | 发放时间 |
| expiresAt | Date? | 到期时间 = grantedAt + 6 个月 |

加入 `moneyfull_iosApp.swift` 的 `ModelContainer` 模型列表，自动获得 CloudKit 跨设备同步——换设备/重装 App，只要登录同一个 iCloud 账号，赠送记录会跟着同步回来，不会重复发放，也不会丢失。

### 3.3 `StoreManager.swift` 改造方案

保持 `isPremium` 对外的读取方式完全不变（其他页面不用改一行代码），内部改成"两路来源合并计算"：

```swift
@Published private(set) var isPremium: Bool = false

private var hasRealSubscription: Bool = false      // 来自苹果 StoreKit 真实校验结果
private var hasActiveLegacyGift: Bool = false       // 来自本地 LegacyGiftGrant 是否在有效期内

private func recomputeIsPremium() {
    isPremium = hasRealSubscription || hasActiveLegacyGift
}
```

- `verifyCurrentEntitlements()`、`purchase()`、交易监听器：把原来直接赋值 `isPremium = ...` 的地方，改成赋值 `hasRealSubscription = ...` 后调用 `recomputeIsPremign()`。
- App 启动时读取 `LegacyGiftGrant`，计算 `hasActiveLegacyGift = isGranted && expiresAt > 今天`，调用一次 `recomputeIsPremium()`。
- 已经是真实付费会员的人，永远不会被判定"老用户福利"覆盖或打断——两路是"或"的关系，真实订阅优先展示（`currentPlanTitle` 优先显示真实订阅方案名，赠送期只在没有真实订阅时显示"体验会员"）。

### 3.4 到期处理

- 到期前 **3 天**：在消息中心插入一条"体验期即将到期"的提醒通知（复用消息中心机制，不用单独做）。
- 到期当天：`hasActiveLegacyGift` 自动变为 `false`，`isPremium` 自动降级，界面无需额外代码兜底。
- 明确不做的事：不做"到期自动扣费"（本来就不经过苹果内购，也没有绑卡，不存在扣费可能）。

### 3.5 边界情况

| 场景 | 处理方式 |
|------|----------|
| 用户换新设备，登录同一 iCloud | `LegacyGiftGrant` 随 CloudKit 同步下来，正常识别，不重复发放 |
| 用户卸载重装，未开 iCloud 同步 | 本地记录清空，新设备上重新判定——如果账本数据也一起丢了，会被当作"新用户"处理（不会二次发放，因为已经没有老账本记录可以证明资格）；如果开了 iCloud，账本和赠送记录都会一起找回 |
| 用户改系统时间 | 存在理论上的绕过可能，无服务器校验兜底。评估为低风险（记账 App，作弊收益低），本次不特殊处理 |
| 体验期内又真实订阅了 | 真实订阅优先，`currentPlanTitle` 显示真实方案，不会"两个身份"混乱展示 |
| **超过领取截止时间（9月18日之后）** | **不再发放福利**，即使用户是老用户且从未领取过。消息中心不插入通知，不弹窗，`isPremium` 保持 false |

## 四、功能二：感谢信弹窗

### 4.1 触发时机

- 老用户升级到新版本后，**第一次打开 App 自动弹出**，且**只弹一次**（复用 3.1 节里"发放福利"那一刻同步触发，不再单独加一个判断）。
- 挂载位置：`ContentView.swift`，写法与现有 `showRatingPrompt`（评分弹窗）的 `.overlay` 模式一致，延迟 1~2 秒弹出，避免和启动动画抢时间。

### 4.2 UI 结构（对应你给的设计稿）

```
┌─────────────────────────────┐
│  [标题区]           [X关闭]  │ ← 渐变/浅色背景，标题"给陪伴的你"
│  给陪伴的你          🤍      │
│  关于会员付费服务的说明        │
│                              │
│  [🗓 6个月免费体验]  [👑] [水獭插画]  ← 装饰区
│                    💬感谢有你，让小满变得更好~
├─────────────────────────────┤
│                              │
│   （信件正文，可上下滚动）      │ ← 白色圆角内容区
│                              │
├─────────────────────────────┤
│      ❤️ 我知道啦（主按钮）     │
└─────────────────────────────┘
```

- 外层卡片：宽度 = 屏幕宽度 - 32pt，圆角 28，居中弹出，半透明黑色背景遮罩。
- 信件正文：**用纯文字渲染**，复用 `ArticleDetailView.swift` 里"`##` 标题 / `•` 列表 / 💡提示"的段落解析逻辑（抽成一个共享组件，见 4.4），支持滚动，不做成图片。
- 底部按钮"我知道啦"：点击关闭弹窗，同时把对应的消息中心通知标记为"已读"。

### 4.3 需要你提供的素材（切图规格）

只需要切**装饰性插画部分**，文字、按钮、背景卡片都由我用代码实现（方便以后改文案不用再找你重新出图）。

### 4.4 组件设计

新建一个通用组件 `NoticeParagraphRenderer`（从 `ArticleDetailView.articleBody` 里把段落解析逻辑抽出来，两处共用，避免重复代码），感谢信弹窗和 4.5 节的消息详情页共用同一份内容数据，不重复维护文案。

信件正文数据以 Swift 数组形式硬编码在代码里（跟 `Article` 的 `paragraphs` 一样，是纯静态文案，不需要额外做后台管理系统）。

## 五、功能三：消息中心（首页铃铛）

### 5.1 数据模型：`AppNotice`（新增 SwiftData 模型）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 固定业务 ID，如 `"legacy_gift_2026"`，方便代码里按 ID 判断"是否已插入过" |
| title | String | 通知标题，如"给陪伴的你" |
| receivedAt | Date | 收到时间，列表按时间倒序 |
| isRead | Bool | 已读/未读，决定铃铛角标 |

同样加入 `ModelContainer`，享受 CloudKit 同步——多设备"已读"状态一致。

### 5.2 页面设计

- **入口**：`Components/CommonViews.swift` 的 `PageHeader`，给 `bell` 图标加上：
  - 点击手势 → 弹出/跳转消息列表页；
  - 右上角小红点角标，`AppNotice.isRead == false` 的数量 > 0 时显示。
- **列表页**（新建 `NoticeCenterView.swift`）：卡片式列表，每条显示标题 + 时间 + 未读小圆点，点击进入详情（复用 4.4 的段落渲染组件），进入即标记已读。
- 空状态：目前只有一条通知也没关系，先做好列表结构，方便以后追加。

### 5.3 与感谢信弹窗的关系

- 弹窗和消息中心详情页展示的是**同一份数据源**（`AppNotice` + 对应的静态正文内容），不是两份文案。
- 自动弹窗只是"第一次的强提醒"，消息中心是"随时可以回看"的入口，两者内容永远一致，改文案只需要改一处。

## 六、功能四：订阅页入口

- 位置：`PaywallView.swift` 的 `PaywallPlansSection`（价格卡片）下方，加一行小字链接："关于会员付费上线的说明 →"
- 点击后弹出同一份感谢信内容（复用 4.4 组件），不重复文案，不影响订阅页原有的购买转化路径。
- 展示逻辑：不判断是否老用户，所有打开订阅页的人都能看到这个入口（新用户点进去看到，也能理解"为什么老用户有特殊待遇"，不会觉得不公平）。

## 八、测试用例 Checklist（上线前必须过一遍）

1. 全新用户（无任何记账记录）安装 App → 不弹感谢信，不发放福利，`isPremium` 保持 false。
2. 老用户（有早于截止日期的记账记录）升级到新版本 → 第一次打开自动弹出感谢信，`isPremium` 变为 true，`currentPlanExpiry` 显示体验期到期时间。
3. 关闭弹窗后重新打开 App → 不再自动弹出，但消息中心铃铛有未读红点。
4. 点击铃铛进入消息中心 → 能看到"给陪伴的你"这条消息，点进去内容跟弹窗一致，点开后红点消失。
5. 订阅页点击"关于会员付费上线的说明" → 打开同一份内容，与前两处文案一致。
6. 老用户体验期内，去真实购买一个月卡/年卡 → 购买成功后 `currentPlanTitle` 显示真实方案名（不是"体验会员"），到期后自动按真实订阅续期规则处理。
7. 手动把设备时间调到体验期结束之后 → `isPremium` 变回 false，付费功能正常恢复锁定，无崩溃。
8. 卸载重装 App（登录同一 iCloud 账号）→ 赠送记录、消息已读状态都能同步找回，不重复发放/重复弹窗。
9. **超过领取截止时间（2026年9月18日之后）** → 老用户即使有记账记录，也不会再收到福利，不弹窗，`isPremium` 保持 false。
