# 数据层接入完整开发计划

## 现状摘要

- 已有 6 个 `@Model`：`Category`、`Project`、`Transaction`、`ChatHistory`、`MemoryRule`、`RecurringBill`
- 无 `VersionedSchema`，靠 SwiftData 自动轻量迁移 + AppStore 内部 UserDefaults 脚本迁移
- LLM 使用阿里云 Qwen（DashScope OpenAI 兼容接口），三个 `@Model` 注册点均在 [`moneyfull_iosApp.swift`](moneyfull_ios/moneyfull_iosApp.swift)
- 所有新 `Project` 字段只要有默认值即可安全轻量迁移

---

## Phase 1: 数据模型层（无 UI 改动）

### 1.1 [`Models/Models.swift`](moneyfull_ios/Models/Models.swift) — 新增两个 @Model

新增 `BudgetItem`：
```swift
@Model final class BudgetItem {
    var id: UUID = UUID()
    var categoryName: String = ""
    var categoryIcon: String = ""
    var categoryColorHex: String = ""
    var amount: Double = 0
    var sortOrder: Int = 0
    var alertThreshold: Double = 0   // 0 = 不预警（Plus 字段）
    var createdAt: Date = Date()
    var project: Project?
}
```

新增 `TimeEntry`：
```swift
@Model final class TimeEntry {
    var id: UUID = UUID()
    var duration: Double = 0
    var granularity: String = "hour"  // "hour" | "day"
    var rate: Double = 0
    var note: String = ""
    var date: Date = Date()
    var createdAt: Date = Date()
    var project: Project?
}
```

扩展 `Project`（全部有默认值，可安全自动迁移）：
```swift
var projectMode: String = "lifestyle"
var budgetCycle: String = "project"
var budgetCycleStartDate: Date = Date()
var budgetCycleDays: Int = 30
var budgetAlertThreshold: Double = 0
var defaultRate: Double = 0
var defaultRateGranularity: String = "hour"
var targetIncome: Double = 0

@Relationship(deleteRule: .cascade, inverse: \BudgetItem.project)
var budgetItems: [BudgetItem]?

@Relationship(deleteRule: .cascade, inverse: \TimeEntry.project)
var timeEntries: [TimeEntry]?
```

在 `Project` 上新增计算属性（纯 Swift 逻辑，不持久化）：
- `budgetItemsAllocated`、`currentCycleSpent`（按 budgetCycle 过滤）
- 搞钱模式：`totalTimeCost`、`totalCost`、`netProfit`、`roi`、`totalHourEquivalent`、`effectiveHourlyRate`
- 生活模式：`totalDays`、`dailyAvgSpend`

### 1.2 [`moneyfull_iosApp.swift`](moneyfull_ios/moneyfull_iosApp.swift) — 注册新模型

三处 `ModelContainer(for: ...)` 均追加 `BudgetItem.self, TimeEntry.self`。

### 1.3 [`Models/AppStore.swift`](moneyfull_ios/Models/AppStore.swift) — CRUD 扩展

- 扩展 `addProject()` 接受新参数（`projectMode`, `budgetCycle`, `targetIncome`, `defaultRate`）
- 扩展 `updateProject()` 同样
- 新增 `BudgetItem` CRUD：`addBudgetItem()`、`updateBudgetItem()`、`deleteBudgetItem()`、`reorderBudgetItems()`
- 新增 `TimeEntry` CRUD：`addTimeEntry()`、`deleteTimeEntry()`
- 新增迁移函数 `migrateV6ProjectMode()`（UserDefaults 守卫，为旧项目设置默认 `projectMode = "lifestyle"`），在 `init()` 的迁移序列末尾调用

## Phase 2: 预算规划数据接入

### 2.1 [`Views/NewProjectView.swift`](moneyfull_ios/Views/NewProjectView.swift)

- 移除 `@State var uiBudgetItems`，保留本地临时数组直至「创建」按钮触发
- `创建` 动作：先 `store.addProject(... projectMode:budgetCycle:...)` 拿到 Project 实例，再循环调用 `store.addBudgetItem()` 写入分类
- 将 `simulateAIBudgetGeneration()` 替换为真实 `LLMService.generateBudgetBreakdown()` 调用（见 Phase 3.1）

### 2.2 [`Views/ProjectDetailView.swift`](moneyfull_ios/Views/ProjectDetailView.swift)

- 删除全部 `@State var uiBudgetItems`、`@State var uiProjectMode` 等 mock 状态
- 预算分类卡读取 `project.budgetItems ?? []`，进度 `spent` 值用 `currentCycleSpent` 计算
- 看板入口卡根据 `project.projectMode` 切换
- 空 `budget == 0` 时隐藏预算分类卡（已在 UI 中判断，确认逻辑正确）

### 2.3 [`Views/BudgetManagementSheet.swift`](moneyfull_ios/Views/BudgetManagementSheet.swift)

- 将 `@Binding var items: [BudgetItemUI]` 改为直接持有 `project: Project` + `@EnvironmentObject store`
- 增删改操作调用 `store.addBudgetItem()` / `store.deleteBudgetItem()` 等
- 周期和预警设置保存回 `project.budgetCycle`、`project.budgetAlertThreshold`

### 2.4 预算周期刷新逻辑

在 `Project` 计算属性中实现 `currentCycleStartDate: Date`：
```swift
// "project" → project.createdAt
// "monthly"  → 本月 1 日
// "custom"   → budgetCycleStartDate + N×budgetCycleDays 的最新周期起点
```
`currentCycleSpent` 过滤 `transactions` 中 `date >= currentCycleStartDate` 的支出。

### 2.5 预算预警 + IP 情绪（Plus）

扩展 [`Services/NotificationManager.swift`](moneyfull_ios/Services/NotificationManager.swift)（或新建 `BudgetAlertManager`）：
- `checkBudgetAlerts(for project: Project)` — 在 `AppStore.addTransaction()` 调用后触发
- 按阈值触发 `UNNotificationContent`，内容参考设计文档第 3.5 节的文案模板
- IP 情绪状态：`Project` 新增计算属性 `budgetEmotionState: BudgetEmotionState`（枚举：`.safe`/`.warning`/`.critical`/`.overBudget`）供 UI 使用

## Phase 3: LLMService 扩展

文件：[`Services/LLMService.swift`](moneyfull_ios/Services/LLMService.swift)

所有新方法遵循现有模式：POST DashScope、`temperature: 0.1`、JSON 解码。

### 3.1 `generateBudgetBreakdown(name:desc:supplement:totalBudget:mode:) async throws -> [BudgetItemUI]`

- System prompt 见设计文档第 3.3 节
- 解码 `{ "budget_items": [...], "reasoning": "..." }` 为 `[BudgetItemUI]`
- 失败时 throw，UI 层降级到手动添加

### 3.2 `generateEarningInsight(project: Project) async throws -> String`

- System prompt 见设计文档第 4.5 节，注入真实计算属性
- 返回格式化洞察字符串（无需 JSON）

### 3.3 `generateProjectReview(project: Project, mode: ProjectMode) async throws -> ProjectReviewResult`

- 新增 `ProjectReviewResult` struct：`aiSummary`, `nextBudgetSuggestions: [(name: String, amount: Double)]`
- 搞钱/生活模式共用同一方法，通过 `mode` 切换 prompt 结构（见设计文档第六节）

### 3.4 自然语言记工时解析（扩展现有管道）

- `TransactionParseResult` 新增可选字段：`timeEntryHours: Double?`, `timeEntryRate: Double?`, `timeEntryNote: String?`
- 更新 `parseTransaction()` 的 system prompt，让模型识别「今天干了 3 小时」→ 输出 `time_entry` 字段
- `AIChatView` 收到含 `timeEntryHours` 的结果时，额外调用 `store.addTimeEntry()`

## 关键技术注意事项

- **SwiftData 自动迁移**：新 `Project` 字段均有默认值，SwiftData 会自动处理；`BudgetItem`/`TimeEntry` 作为全新 @Model 不存在旧数据冲突
- **CloudKit 级联关系**：`BudgetItem.project` 和 `TimeEntry.project` 用 `deleteRule: .cascade, inverse:` 声明，确保项目删除时子记录同步清除
- **LLM 调用隔离**：三个新方法独立，不修改现有 `parseTransaction()` 管道
- **Info.plist**：导出图片需要添加 `NSPhotoLibraryAddUsageDescription`
