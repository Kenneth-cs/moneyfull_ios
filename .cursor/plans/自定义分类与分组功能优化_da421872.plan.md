# 新增分类与自定义大类功能优化方案

## 1. 目标
解决新增子分类后无法显示的问题，并在新增分类和管理页面中，完整支持大类（`groupName`）的选择与自定义，使系统的分类体系更加灵活且不再出现“幽灵分类”。

## 2. 方案细节

### 2.1 数据层与核心接口改造
- 修改 **[moneyfull_ios/Models/AppStore.swift](moneyfull_ios/Models/AppStore.swift)**
  - 改造 `addCategory` 接口：增加 `groupName: String` 和 `transactionType: String` 参数，确保新建分类保存时能绑定到正确的大类及收支类型中。
  - 改造 `updateCategory` 接口：同样增加 `groupName` 字段，以便在系统管理页面支持编辑并修改分类的分组归属。

### 2.2 新增分类组件改造
- **获取上下文环境**
  - 在 **[moneyfull_ios/Views/AddRecordView.swift](moneyfull_ios/Views/AddRecordView.swift)** 中，调用 `QuickAddCategorySheet` 时，将当前 `CategorySelectionView` 所处的 `selectedTab`（如“吃喝”）和 `type` 传递进去。
- **新增“所属分组”选择器**
  - 修改 **[moneyfull_ios/Views/AddRecordView.swift](moneyfull_ios/Views/AddRecordView.swift)** 下方的 `QuickAddCategorySheet`：
  - 增加一个“所属大类”的选择 UI（Menu 或横向滑动标签）。
  - 默认选中当前外部传入的 `selectedTab`（如果是“常用”或“全部”，则默认提供当前收支类型的首个默认组或“其他”）。
  - 增加一个 **“+ 自定义新分组”** 按钮。点击后，切换成 TextField 让用户手填一个全新的大类名称。
  - 更新 `onSave` 闭包签名，将新的 `groupName` 传递出去进行保存。

### 2.3 动态大类 Tab
- 改造 **[moneyfull_ios/Views/CategorySelectionView.swift](moneyfull_ios/Views/CategorySelectionView.swift)**
  - 废弃写死的 `["吃喝", "居家", "出行", ...]` 数组。
  - **动态计算 Tab**：遍历 `typeCategories`，提取所有不为空的 `groupName` 进行去重。
  - **排序规则**：
    1. 首位固定为 “常用”
    2. 接下来是系统预设核心分组（保持吃喝、居家、出行等高频词靠前的原有顺序）
    3. 然后是用户创建的其他新增分组
    4. 末尾固定为 “全部”
  - **效果**：用户只要建了一个带有新 `groupName` 的分类（例如“宠物”），顶部就会立即动态长出一个“宠物”的横向 Tab。

### 2.4 分类管理页升级
- 改造 **[moneyfull_ios/Views/CategoryManagementView.swift](moneyfull_ios/Views/CategoryManagementView.swift)**
  - 将原本只分“系统”和“自定义”两个大块的列表结构，重构为**基于 `groupName` 划分 `Section`**（例如：吃喝组、居家组、自定义的旅游组等）。
  - 每一组内部再列出该组下所有的子分类（无论是系统还是自定义）。
  - 在该页面的新增/编辑表单 `CategoryFormSheet` 里，同步加上“所属分组”的选择与新建功能。
  - **轻量级管理设计**：当用户把某个自定义大类里的所有子分类都删光或者移到其他大类时，该大类由于没有任何关联数据，其对应的 Section 和记账页 Tab 就会自动消失，无需做复杂的“删除分组”逻辑。
